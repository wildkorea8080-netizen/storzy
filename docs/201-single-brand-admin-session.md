# 단일 브랜드 파일럿 관리자 세션

기준일은 2026-08-21이다. 첫 출시 형태는 단일 브랜드 파일럿으로 정하고, 공용 관리자 토큰을 매 API 요청에 노출하던 방식에서 서버 세션 방식으로 전환한다. 기존 Bearer 인증은 자동화와 점진적 전환을 위해 당분간 호환 경로로 유지한다.

## 구현 범위

- `POST /api/auth/admin/session`: 관리자 토큰을 한 번 검증하고 서버 세션을 생성한다.
- `GET /api/auth/admin/session`: 현재 쿠키의 인증 상태를 반환한다.
- `DELETE /api/auth/admin/session`: 현재 세션을 폐기하고 쿠키를 제거한다.
- `/admin/login`: 한글 관리자 로그인 화면을 제공한다.
- 동일 IP의 로그인 실패는 기본 15분 동안 5회까지만 허용하며 초과 시 `429`와 `Retry-After`를 반환한다.
- 유효한 세션을 감지한 관리자 화면은 토큰 입력란 대신 세션 연결 상태와 로그아웃 버튼을 표시한다.
- 관리자 공통 요청 계층은 서버 세션 모드에서 레거시 화면이 만든 `Bearer session` 표시 헤더를 제거하고 `same-origin` 쿠키만 전송한다.
- 쿠키로 인증된 변경 요청은 `Origin`과 Fetch Metadata를 검사해 교차 사이트 요청을 `403 ADMIN_CSRF_REJECTED`로 차단한다.
- `/admin/security`에서 활성 세션과 최근 로그인 감사 이력을 확인하고 모든 활성 세션을 일괄 종료할 수 있다.
- 현재 세션을 구분해 표시하며 각 세션을 개별 종료할 수 있다. 현재 세션을 종료하면 로그인 화면으로 이동한다.
- 로그인 성공·실패·제한, 로그아웃, 전체 종료 이벤트를 기록하되 접속 IP 원문은 저장하지 않고 SHA-256 digest만 남긴다.
- 인증 감사 이벤트는 기본 90일, 만료·폐기 세션 기록은 기본 30일 보존하고 보안 화면에서 만료 기록을 정리한다.
- 운영 환경에서는 `admin-auth-retention` CronJob이 5분마다 보안 경보 전송과 보존 정리를 실행하고 process heartbeat로 성공·실패를 보고한다.
- 로그인 제한 이벤트는 15분 단위로 중복 제거된 보안 경보가 되며, 설정된 HTTPS Webhook으로 timestamp와 HMAC-SHA256 서명을 포함해 비동기 전송한다.
- 보안 경보는 확인·해결 상태와 처리 이력을 가지며 실패한 Webhook 전송은 사유를 남겨 수동 재시도할 수 있다. 보안 화면의 연결 테스트는 실제 경보와 구분되는 `CONNECTION_TEST` payload를 전송한다.
- 세션 원문은 응답의 `HttpOnly`, `SameSite=Strict` 쿠키에만 전달한다.
- DB에는 SHA-256 digest만 저장하며 만료·마지막 사용·폐기 시각을 기록한다.
- 운영 환경 쿠키에는 `Secure`가 자동으로 추가된다.
- 세션 기본 유효 시간은 8시간이며 `ADMIN_SESSION_TTL_SECONDS`로 5분~7일 범위에서 조정한다.
- 로그인 제한은 `ADMIN_LOGIN_MAX_ATTEMPTS`, `ADMIN_LOGIN_WINDOW_SECONDS`로 조정한다. 현재 단일 프로세스 파일럿 범위에서는 프로세스 메모리 기준이며, 수평 확장 시 Redis 등 공유 저장소로 교체한다.

## 다중 사용자 확장 경계

현재 세션은 단일 관리자 권한만 표현한다. 다중 tenant 전환 시 쿠키 계약과 세션 digest 저장 방식은 유지하고 다음 필드를 확장한다.

1. 세션에 `user_id`를 연결한다.
2. 사용자와 workspace membership을 추가한다.
3. 요청 workspace에 대해 `OWNER`, `OPERATOR`, `VIEWER` 역할을 검사한다.
4. 비밀번호 또는 외부 인증 공급자, 초대·복구·MFA 흐름을 결정한다.

따라서 이번 구현은 폐기할 임시 로그인 화면이 아니라 다중 사용자 인증의 세션 계층으로 재사용한다.

## 운영 확인

1. migration `077_admin_sessions.sql`을 적용한다.
2. `ADMIN_API_TOKEN`과 운영 HTTPS 주소를 설정한다.
3. `/admin/login`에서 로그인한다.
4. Bearer 헤더 없이 보호 API가 성공하는지 확인한다.
5. 로그아웃 후 같은 쿠키로 보호 API가 401을 반환하는지 확인한다.
6. `/admin/security`에서 감사 이벤트와 활성 세션 수를 확인한다.

로그인 실패 응답에는 입력 토큰이나 설정 토큰을 기록하지 않는다. 관리자 화면과 API 응답은 캐시하지 않는다.

브라우저의 `sessionStorage`에는 비밀값이 아닌 `session` 표시값만 둔다. 실제 Bearer 토큰 경로는 배포 검증과 서버 간 자동화의 하위 호환을 위해 유지하며, 서버 세션으로 동작하는 브라우저 요청에는 전송하지 않는다.
